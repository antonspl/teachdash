# Proposal

Issue: #197 (closes it). Redesign plan step 3a (`.agents/design/design-code.md`, "Redesign plan"; "States", "Buttons, icons and tooltips", "Fields", "Copy and languages"). It also takes the two review follow-ups on #197: the quiet button icon inset (from PR #215, #195) and the focus ring that hid the error border (from PR #216, #196).

## Clarifications

Decisions by the engineer:

1. Button variants: 3a adds `quiet`, danger text and muted word now (besides primary, secondary and danger), and the `icon` prop accepts any icon from the shared set (`frontend/src/ui/icons.tsx`). Nothing renders the new variants yet; they are proven by unit tests and listed as unreachable states. Reason: the builder issues #115-#120 depend on 3a.
2. The teacher-row "Deactivate" stays a filled danger button until 6a (#203) restyles the row actions; spec `web-client` R27-S4 stays as it is.
3. Secondary button text colour becomes `--color-text` (today `--color-accent`). The design code does not decide it; accent is reserved for primary buttons, links, focus and the bars (design-code Direction).
4. The password Show/Hide toggle becomes a real `Button` (secondary look, weight 600), with `aria-pressed` and its aria-label passed through (en "Show {{label}}" as today, with no colon; ru «Показать: {{label}}»); the hand-styled `.toggle` in `Field.module.css` goes.
5. Full-width phone variant: used only for the lone submit on login and set-password, at narrow widths (`@media (max-width: 63.999rem)`). The stacked dialog foot belongs to #198 (3b); 3a does not change ButtonRow layout.
6. Icon inset on icon-led buttons ("Add teacher"): the reviewer's fix from the #215 comment on #197, verbatim: "a role-named token such as `--button-icon-inset` and `padding-inline-start: calc(var(--space-group) - var(--button-icon-inset))` on icon-led buttons, keeping the gap at `--space-inline`". Token `--button-icon-inset: 0.1875rem` (about 3px, the empty margin inside the 20-unit plus at stroke 1.75). Applied through a Button class set when `icon` is present (no `:has`), logical properties.
7. One global `:focus-visible` rule in `frontend/src/styles/base.css`: `outline: var(--border-width-strong) solid var(--color-focus-ring); outline-offset: var(--focus-offset)`; never `outline: none` (design-code States "Focus"). It also fixes the #216 follow-up: the browser's default ring hid the 1px error border.
8. Field error: the message under the field, `AlertIcon` at `--icon-size-small` (`aria-hidden`) left of the text, aligned to the first text line, `--space-inline` gap, text wraps under the text not under the icon, never truncated; message `--text-small`, `--line-height-small`, `--color-danger-text`. Error border `--border-width-strong` `--color-danger-text` with `padding-inline-start: calc(var(--space-group) - var(--border-width))` so text and the select arrow do not move; height unchanged. `aria-invalid="true"` and `aria-describedby` (exist today). No `role="alert"` on field errors (it would double-announce with focus and the description).
9. The live password hints of `web-client`/`web-profile` R14 ("at least 8 characters", "do not match") keep going through the `error` prop, so while typing they show as errors (2px red border, icon, `aria-invalid`). R14 does not change.
10. Busy label on: the form submits (Sign in, Set password, Save, Change password, Create teacher), the Confirm button of the deactivate dialog, and the pressed row button (New invite link / Password reset link / Reactivate); `runRowAction` must know which action was pressed. Log out (no in-flight state today) is out of scope: a separate follow-up issue (the main agent files it).
11. Busy label keys: one key per button, named after its action, for example "Signing in…", "Setting password…", "Saving…", "Changing password…", "Creating…", "Deactivating…", and the row actions' own busy words. Ellipsis is the single "…" character. The spec-writer proposes the exact English strings (design.md D9); the engineer sees them at the spec gate.
12. Russian busy labels are nouns («Вход…», «Сохранение…», «Создание…», «Смена пароля…», «Деактивация…» and so on), as an exception to the infinitive rule for buttons, like the existing noun exceptions. The rule is added to design-code "Copy and languages" (one or two lines).
13. Busy state = native `disabled` + `aria-busy="true"` + the busy label, no spinner (design-code States "Loading"). Width kept: the idle and the busy label stacked in one grid cell, the inactive one `visibility: hidden` and `aria-hidden`, so the busy button has the width of the longer label in any language with no measuring and no inline style (Clarification 28 changes this: the stacking is only while busy). No live-region announcement at request start; the result is announced by the existing `StatusMessage`.
14. Tests: a busy button is found by its busy-label key (`getByRole('button', {name: en.<key>})`), with `aria-busy="true"` and `disabled` asserted; where a test re-queries the button mid-request, it holds the element reference instead (as `AdminTeachersPage.test.tsx` R5-S4 does). No test ids. A check is added to `e2e/russianFit.spec.ts` that the Russian busy labels fit at 360.
15. Icon-led select: an `icon` prop on `Select` (a decorative globe, muted like the arrow, `aria-hidden`, its own data attribute, placed OUTSIDE `[data-select-arrow]` so R28-S3 holds), at `left: calc(var(--border-width) + var(--space-group))`, with `padding-inline-start` = group + icon + inline; the arrow keeps `--space-group` from the inner right edge, so both gaps are `--space-group`. `web-client` R13 changes for a select that leads with an icon only; the default select keeps R13 as is. Used by the UI language select (header, and `LanguageRow` in `<main>` on login and set-password).
16. `--lang-select-width` rises from 9rem to 10.5rem (with the icon, «Русский» had zero margin at 9rem). `tokens.test.ts` updates accordingly.
17. The vendored-doc drift is fixed in this PR: the `.agents/design/refactoring-ui-patterns.md` focus example (line 91) to `--border-width-strong` and `--color-focus-ring` as design-code says; the `.agents/design/accessibility-patterns.md:29` skip-link padding to `0 var(--space-group)`. One-line edits, as tasks for the implementer, with the exact before and after lines in design.md D11. Extended: the stale focus statements in `accessibility.md` (lines 140-146: the non-existent `--focus-ring-width` and `--focus-ring-offset` and `--color-accent`), `refactoring-ui-patterns.md:99` and `checklist.md:28` ("a thicker outline or an offset is a new role-named token", now false) are fixed too.
18. The review items "the space before a full stop after a control" and "the 2rem row focus ring meeting the border" are dropped from 3a: nothing in the app shows them (no 2rem row buttons exist yet). They move to 4a (#199, IconButton); the main agent comments on #199. The design-code "Redesign plan" small-items line is updated to match (design.md D11).
19. Decided by sources, confirmed by the engineer: button height `--control-height` (2.5rem `pointer: fine`, 2.75rem touch), padding `0 var(--space-group)`, weight `--weight-strong`, `--line-height-tight`; hover, active and disabled per design-code States (primary `--color-accent-hover` and `--color-accent-active`; secondary and quiet hover `--color-surface-sunken`, active `--color-neutral-background`; danger `--color-danger-action-hover`; disabled `--opacity-disabled` and `cursor: not-allowed`); transitions `--duration-fast` on colour, border and opacity only; an icon on a button only for a create action's plus ("Add teacher" yes, "Create teacher" no); Cancel is secondary; field hover border `--color-text-muted` (not on an invalid, a disabled or a read-only field); the read-only field (the IssuedLink input) keeps the sunken fill and has no hover; fields keep `min-height: var(--control-height)`; disabled inputs and the toggle get `--opacity-disabled`, `cursor: not-allowed` and native `disabled`. Out of 3a: header buttons stay until 5a and 5b; "Add teacher" stays in Toolbar until 6a; the dialog labels "Keep active" and "Deactivate" are 6a; the dialog foot structure is #198; the "(optional)" marker is #165.
20. Busy labels mirror the idle action's name ("an action keeps the same name through the whole flow"): en `adminTeachers.busy.inviteLink` "Creating invite link…", `adminTeachers.busy.resetLink` "Creating reset link…"; ru set-password «Сохранение пароля…», reactivate «Повторная активация…», reset link «Создание ссылки для сброса…». The other labels are unchanged (design.md D9). The Russian 360 check (Clarification 14) covers these.
21. No minimum duration or delay for the busy state: a near-instant request may flash the busy label and the dim. The button must be disabled at once to block a second press; a delay would need a new duration token and a timer.
22. Hover (buttons and fields) is applied only under `@media (hover: hover)`, so a tap on a touch screen leaves no sticky hover. One line is added to design-code States.
23. The icon-led select keeps box-equal gaps as design-code says (`--space-group` from the icon box and from the chevron box); the visible glyph gaps differ (about 14px for the globe, 17px for the chevron). Accepted; the visual reviewer judges the screenshots.
24. `--button-icon-inset` is the plus icon's empty margin, applied to every icon-led button (other icons may differ by up to 1px; accepted).
25. The live R14 hints change while the user types and reach screen readers only through `aria-describedby`, not announced on change (WCAG 4.1.3). This exists on `main` and is not made worse; it is out of scope, follow-up #246.
26. The password toggle changes width between "Show" and "Hide" and shifts the input. This exists on `main` and is out of scope, follow-up #247.
27. Requirement count: only new requirements count against the limit of 6 (2 added, 10 modified), as in `ui-auth` and `teacher-language`. Variant and prop names `quiet`, `dangerText`, `muted`, `busy`, `busyLabel`, `fullWidth`, `ariaLabel`, `ariaPressed` and the `FieldError` component are accepted; R27 is renamed "Button roles and states"; the design-code token table gets `--button-icon-inset` `0.1875rem` and `--lang-select-width` `10.5rem`; the danger fill has no active step.
28. The busy button's width never shrinks but may grow while busy. An idle button renders only its idle label, at its natural width (the normal `0 var(--space-group)` padding). While busy, both labels sit in one grid cell (the idle one `visibility: hidden` and `aria-hidden`, the busy one shown), so the busy width is the longer of the two; when the busy label is shorter (for example «Вход…» against «Войти») the width does not change. This returns to the original design-code States "Loading" wording, "its minimum width is kept", so the F14 edit of that line is dropped. Reason: with both labels always in the DOM, idle buttons reserved the busy label's width and looked unbalanced all the time (en "Confirm" 136px for a word that needs about 85px, "Save" 91 against about 65, "Sign in" on desktop 115 against about 80, ru reset link 273px), while the busy state lasts a moment; growing moves almost nothing (the submits are alone or last in their row; only the en teacher row's "Deactivate" shifts by about 10px). `AdminTeachersPage.test.tsx` R23-S2 (it reads the dialog button's `textContent`) stays unchanged: idle, only the idle label is in the DOM.

29. R30-S1 checks the keyboard focus ring on the language select, email input, password input, password visibility toggle and sign-in button on the login page. It checks the link on the not-found page, where the link to the start page already exists. Check every named control individually as keyboard focus reaches it.

## Research angles and conclusions

Angles: two `frontend-researcher` angles (buttons, icons and the busy state; fields, error and states, with the icon-led select), and one angle on the specs and tests affected.

- Already in the specs from #196: `web-client` R27 (variants, no green; S2 pins the variant type, S4 the filled row Deactivate), R28 (chevron; S2 pins `.arrow` and `.select`, S3 "no other svg" in the arrow), R26-S2 (the error border colour), R24 (token names and values in `tokens.test.ts`), R23 (icons on buttons).
- Tests that break with busy labels (they read the button by its idle name while the request runs): `web-auth` R1-S4 (`App.test.tsx:255-272`); `web-profile` R2-S8 (`ProfilePage.test.tsx:386-405`) and R3-S9 (`:998-1020`); `web-admin-teachers` R2-S5 (`AdminTeachersPage.test.tsx:160-164` `submitButton()`, also called while busy at about 345, 455, 998 and 1006), R5-S4 (`:936-956`, `deactivateButton(row)`) and the confirm `confirm()` helper (`:1042-1055`). Reads by the idle name outside a busy state are fine (listed in design.md D10).
- Other tests to update: `cssRules.test.ts` (R26-S2), `tokens.test.ts` (the new token and the 10.5rem width), `Button.test.tsx`, `Select.test.tsx` (the error icon is `aria-hidden`, so description-text equality holds), the i18n parity and copy tests, and `e2e/selectArrow.spec.ts` (its helper reads `paddingLeft` as the arrow gap, so the icon-led select needs its own measure).
- Risks: a disabled focused button can lose focus (R14-S12, R17). The buttons are already natively disabled while busy today, so the busy state adds no new focus loss (design.md D2). Russian busy labels at 360.

## What changes

- `web-client` R29 (busy button) and R30 (field focus, error and states) are new. R13 (the icon-led select), R24 (one new token, the language select width), R26 (S2, the 2px error border) and R27 (renamed "Button roles and states": variants, states, icon, full width) are modified.
- `web-auth` R1 (S4), `web-profile` R2 (S8) and R3 (S9), `web-admin-teachers` R2 (S5), R4 (S2) and R5 (S4) are modified: the "not sent twice" scenarios read the button by its busy label. Nothing else in them changes.
- Count: two requirements are new; the others are edits of existing ones, so the 6-requirement limit holds for the new ones (earlier changes edited more requirements than they added).
- Button gets the new variants, the states, `icon` for any shared icon, the icon inset, the busy state and the phone full-width variant. Field gets the error and state rules, the password toggle becomes a Button, and `Select` gets the `icon` prop for the UI language select.
- `base.css` gets the one global `:focus-visible` rule. `tokens.css` gets `--button-icon-inset` and `--lang-select-width` 10.5rem; the design-code token table is updated to match.
- New en and ru busy labels; `runRowAction` tracks the pressed action.
- Design docs: the design-code copy rule, token rows and small-items line; two vendored-doc lines.
- Tests: Vitest for the components, the CSS as text and the bundles, Playwright for focus, the field error, the icon-led select, the busy width and the Russian fit; before and after screenshots of every page state.
